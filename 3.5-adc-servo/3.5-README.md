# 3.5 — Potentiometer-controlled servo: math, setup and decisions

## 1. Task

- The potentiometer controls the servo shaft in a **1:1 ratio**: 1° of knob = 1° of shaft.
- Where pot and servo ranges don't match, that part is filtered out: **only the matching portion of the range is used**.
- The angle of deviation from the **far-left position** is logged to the console.

**Interpretation.** A pot turns about 270–300°, an SG90 covers 180°. So we use a **180° window** of knob travel, centered on the pot's mechanical middle, and map it 1:1 onto the servo. Outside the window the servo **clamps**: it waits at 0° or 180° while the knob keeps turning. "Filtered out" also covers ADC noise, handled by the EMA filter and the deadband.

## 2. Current setup (no transistor)

```
                          ESP32-S3 DevKitC-1 (powered by USB)
                         +------------------------------+
   POT end A ------------| 3V3                          |
   POT wiper ------------| GPIO4  (ADC1_CH3)            |
   POT end B ------+-----| GND                          |          SG90 servo
                   |     | GPIO5  (LEDC PWM) -----------+------->  orange  SIG
                   |     +------------------------------+          red     +5 V  <---- MODULE 5V
                   |                                               brown   GND   <--+
                   |                                                                |
                   +---------------------- common GND ------------------------------+---- MODULE GND
```

| Wire | Goes to |
|---|---|
| Pot end A | ESP 3V3 (never 5 V: the wiper feeds the ADC pin directly) |
| Pot wiper (middle pin) | GPIO4 = ADC1_CH3 |
| Pot end B | ESP GND |
| Servo orange (signal) | GPIO5, directly (SG90 accepts 3.3 V logic) |
| Servo red (middle) | Power module 5 V (module jumper on 5 V) |
| Servo brown | Power module GND |
| ESP GND | Power module GND — **common ground is mandatory** |

- **ADC1, not ADC2**: ADC2 is unusable while Wi-Fi runs.
- **Never connect the module's 5 V to the DevKit's 5 V pin** while USB is plugged in. Only the grounds are joined.
- The servo's current comes from the module, so it can't pull down the ESP32's supply.

## 3. Capacitors (not fitted now — for future reference)

| Capacitor | Where | Job |
|---|---|---|
| 470–1000 µF electrolytic | Servo 5 V to GND, at the servo connector | Energy reservoir for current bursts |
| 100 nF ceramic | Next to the electrolytic | High-frequency motor noise (electrolytics are slow) |
| 100 nF ceramic | Pot wiper to GND | Low-pass filter for the ADC input |

**Supply sag.** A servo draws bursts of several hundred mA (SG90 stall ≈ 0.7 A). Wires have resistance R, so the rail drops:

```
ΔV = I · R
```

If that rail also feeds the ESP32, its regulator drops out and the brownout detector resets the board. A capacitor at the servo supplies the fast part of the burst and recharges through R — an RC circuit:

```
τ = R · C
```

It only covers bursts **shorter than about τ**. For long loads (a stalled servo) only a lower R helps: stronger supply, shorter and thicker wires. That's why the separate module is the real fix here, and why the caps are optional. Add the 470 µF one if the servo jitters or the module is weak.

**Wiper filter.** The pot's source resistance is at most R/4 (2.5 kΩ for 10 kΩ at mid-travel):

```
f_c = 1 / (2π · R · C) = 1 / (2π · 2.5 kΩ · 100 nF) ≈ 640 Hz
```

Much faster than a hand turns a knob, but it removes noise coupled from the servo wires.

Never disable brownout detection to "fix" servo resets.

## 4. The signal: µs and pulses

- `us` = **µs = microseconds** (millionths of a second). `µ` isn't allowed in C names. 1500 µs = 1.5 ms; µs keeps values whole.
- Every **20 ms** (50 Hz), the pin is HIGH for a short time, then LOW. The HIGH part is the **pulse**; its duration is the **pulse width**, and the width is the command:
  - ≈ 500 µs → 0°, ≈ 2400 µs → 180°, linear in between.
- **The servo reads pulse width, not duty cycle.** Changing the frame rate changes the duty cycle but not the angle.

LEDC math (lecturer's 13-bit timer):

```
ticks per frame = 2^13 = 8192
tick length     = 20,000 µs / 8192 ≈ 2.44 µs
ticks           = pulse_us · 8192 / 20,000            1500 µs → 614 ticks
one degree      ≈ (2400 − 500) / 180 ≈ 10.6 µs ≈ 4 ticks
```

Multimeter check (DC volts on GPIO5):

```
V_avg = (pulse_us / 20,000) · 3.3 V                    1500 µs → ≈ 0.25 V
```

## 5. Conversions: one scale onto another

### 5.1 Two rulers

`deg_to_us` and the window are the **same** operation. Example, °C → °F (0 °C = 32 °F, 100 °C = 212 °F), for 50 °C:

1. Distance from the start of scale A: `50 − 0 = 50`
2. Fraction of A's length: `50 / (100 − 0) = 0.5`
3. Same fraction of B's length: `0.5 · (212 − 32) = 90`
4. Shift to where B starts: `32 + 90 = 122 °F`

**Percentage along A → same percentage of B's length → shift by B's start.**

```
out = out_start + (in − in_start) / (in_end − in_start) · (out_end − out_start)
                  └─ 1. distance ─┘   └─ 2. ÷ length A ┘   └─ 3. · length B ─┘
      └─ 4. start of B
```

- **Length = end − start** (1900 µs for 500…2400, not 2400).
- Both scales are evenly spaced, so the graph is a **straight line through two known points**. That's why calibration measures exactly two points per device.

### 5.2 In the code

`deg_to_us` — A = 0…180° (starts at 0, so the distance is just `deg`), B = `us_at_0`…`us_at_180`:

```
us = us_at_0 + deg · (us_at_180 − us_at_0) / 180
```

Window — A = `raw_at_0`…`raw_at_180` (ADC codes), B = 0…180° (starts at 0, so nothing is added):

```
deg = (code − raw_at_0) · 180 / (raw_at_180 − raw_at_0)
```

Example (500 / 2400 µs), 90°: 90 · 1900 = 171,000 → / 180 = 950 → 500 + 950 = **1450 µs**.

### 5.3 Multiply before dividing

Integer division drops the fraction: `90 / 180 = 0`.

| Order | 90° | Result |
|---|---|---|
| Divide first | 90 / 180 = 0 → 0 · 1900 = 0 → 500 + 0 | 500 µs — wrong for every angle < 180 |
| **Multiply first** | 90 · 1900 = 171,000 → / 180 = 950 → 500 + 950 | **1450 µs** |

Make the numbers big first, divide last: the division loses less than one unit.

### 5.4 Clamp

```
clamp(x, lo, hi):  x < lo → lo;  x > hi → hi;  otherwise x
```

Outside the window the fraction drops below 0 or above 1, so the formula gives angles below 0 or above 180. The clamp caps them — this *is* the "only the matching portion" rule. `deg_to_us` clamps again (defense in depth).

### 5.5 Signed math

- `code − raw_at_0` is negative left of the window, so everything that gets subtracted is `int32_t`.
- With `uint32_t`, a negative result wraps to ≈ 4.29 billion → clamp returns **180 instead of 0** → servo goes to the wrong end. One unsigned operand makes the whole expression unsigned.
- `deg_to_us` computes the span signed: `(int32_t)us_at_180 − (int32_t)us_at_0`, converts to `uint32_t` only at the end. A reversed servo (`us_at_0 > us_at_180`) then just works.

## 6. EMA filter (exponential moving average)

### 6.1 Don't jump, move part of the way

Readings are noisy (2048, 2061, 2039, … with a still knob). Keep one running average and move it a fraction α of the way toward each new reading:

```
new_avg = old_avg + (reading − old_avg) · α          "α of the gap"            (used in code)
new_avg = old_avg · (1 − α) + reading · α            "keep 80 %, take 20 %"    (same thing)
```

It's α of the **gap**, not α of the reading: 1000 + (2000 − 1000) · 0.2 = **1200** (not 1000 + 2000 · 0.2 = 1400).

| Step | Gap to 2000 | Move 20 % | New average |
|---|---|---|---|
| 1 | 1000 | 200 | 1200 |
| 2 | 800 | 160 | 1360 |
| 3 | 640 | 128 | 1488 |

A single spike (one reading of 1100 among 1000s) moves the average by only 20.

### 6.2 One number, not a ring buffer

- A **moving average** keeps the last N readings in a ring buffer: equal weight, then forgotten. 4·N bytes.
- The **EMA** stores **one number**, which already contains every past reading with shrinking weights:

```
newest 20 %,  then 16 %,  12.8 %,  10.24 %, …      (each = previous · (1 − α))
```

Shrinking by a constant factor = "exponential". 4 bytes of state.

### 6.3 Choosing α

```
time constant τ ≈ loop period · 256 / alpha_q8         (20 ms · 256 / 51 ≈ 100 ms)
```

| `alpha_q8` | α | τ | Feel |
|---|---|---|---|
| 256 | 1.0 | 0 | no filtering |
| 128 | 0.5 | ≈ 40 ms | snappy, jitter leaks through |
| **51** | **0.2** | **≈ 100 ms** | **default** |
| 13 | 0.05 | ≈ 400 ms | smooth, visibly lags |

### 6.4 Valid range: 1 … 256

| `alpha_q8` | Behaviour |
|---|---|
| 0 | moves 0 % of the gap: frozen forever |
| 1 … 256 | smooth approach (valid) |
| 257 … 511 | overshoots the target and rings |
| 512 | oscillates forever |
| > 512 | overshoots more each step, diverges |

`servo_follow_init()` rejects anything outside 1…256.

## 7. Q8 fixed point

### 7.1 Counting in "cents"

Integers can't hold 0.2 or 1200.4. Like storing euros as cents, we store everything in **1/256ths** (256 = 2^8, binary-friendly). "Q8" = 8 bits of fraction.

| Name | Meaning | Example |
|---|---|---|
| `SERVO_FOLLOW_Q8_ONE` | 1.0 | 256 |
| `alpha_q8` | α | 0.2 · 256 ≈ **51** (= 0.1992) |
| `x_q8 = raw · 256` | reading in Q8 | 2000 → 512,000 |
| `ema_q8` | average in Q8 | 1200.4 → ≈ 307,302 |
| `· alpha_q8 / 256` | "· α" | · 51 / 256 ≈ · 0.2 |
| `code = ema_q8 / 256` | back to ADC units | 614,400 → 2400 |

```
ema_q8 = ema_q8 + (x_q8 − ema_q8) · alpha_q8 / 256
```

is exactly `average + gap · 0.2`, counted in 256ths.

### 7.2 Why the state is in Q8 too

With a plain-integer average, the step `gap · alpha_q8 / 256` truncates to 0 whenever `gap · alpha_q8 < 256`. The filter stops short of the target:

```
plain int:  stalls within 256 / alpha_q8 counts      (alpha 51 → ≈ 5,  alpha 10 → ≈ 25 counts ≈ 1.7°)
Q8 state:   stalls within   1 / alpha_q8 counts      (alpha 51 → ≈ 0.02 counts)
```

### 7.3 Why 8 bits

The product `(x_q8 − ema_q8) · alpha_q8` must fit in `int32_t` (max ≈ 2.147 billion). With F fraction bits and a 12-bit ADC:

```
worst case = 4095 · 2^F · 2^F = 4095 · 2^(2F)      → each fraction bit costs 2 bits
rule:      ADC_BITS + 2 · F ≤ 30                     (1 bit of safety margin)
```

| Format | α = 0.2 stored as | Stall gap | Worst case | Verdict |
|---|---|---|---|---|
| Q0 | 0 | never moves | 4,095 | unusable |
| Q4 | 3 = 0.1875 | 0.33 counts | ≈ 1 M | coarse |
| **Q8** | **51 = 0.1992** | **0.02 counts** | **≈ 268 M** | **8× headroom** |
| Q9 | 102 = 0.1992 | 0.01 counts | ≈ 1.07 G | tight |
| Q10 | 205 = 0.2002 | 0.005 counts | ≈ 4.3 G | overflows |

Q8 is a chosen number format, not a hardware property. With a 16-bit ADC it would overflow; Q7 would be the maximum.

### 7.4 Practicalities

- Divide by 256, don't shift: `>>` on negative numbers is implementation-defined in C.
- `ema_q8` is signed: the gap is negative when the knob turns down.
- Readable config, evaluated at compile time (no float on the chip):

```c
#define Q8(x)            ((int32_t)((x) * 256.0 + 0.5))
#define BOARD_ALPHA_Q8   Q8(0.2)    /* = 51 */
```

## 8. Deadband

```
if |deg − last_deg| ≥ deadband_deg:  update servo, last_deg = deg, return true
else:                                hold, return false
```

Even filtered, the angle flickers between neighbours (112 ↔ 113); each flicker is a new pulse, a twitch and a buzz. Deadband 1 blocks repeats of the same value; 2 also blocks the flicker. Cost: slow movements are ignored until they add up.

```c
static inline int32_t abs_i32(int32_t x) { return (x < 0) ? -x : x; }
```

Angles are clamped to 0…180 first, so the difference stays within −180…180.

## 9. Calibration = two points per line

| Constant | Unit | Measured at | Mode |
|---|---|---|---|
| `BOARD_RAW_AT_0` | ADC code | knob at **center − 90°** | 1 |
| `BOARD_RAW_AT_180` | ADC code | knob at **center + 90°** | 1 |
| `BOARD_US_AT_0` | µs | horn exactly on the **0° (far-left) mark** | 2 |
| `BOARD_US_AT_180` | µs | horn exactly on the **180° mark** | 2 |

Each pair is the two known points of one straight line (section 5.1).

Traps:
- **Pot: not the stops.** The ends read a flat 0 / 4095 (ADC dead zone, saturation near 3.1 V). Using them squeezes ~300° of knob onto 180° → 0.6:1, not 1:1.
- **Servo: not where it hums.** Humming = mechanical stop = stall current.

Expected window edges (linear pot): 270° travel → ≈ 680 / 3410; 300° → ≈ 820 / 3280. About 15 ADC counts per degree.

Final check: knob at C − 90°, C, C + 90° → horn at 0°, 90°, 180°. Wrong direction → swap `BOARD_US_AT_0` and `BOARD_US_AT_180`.

## 11. Decisions in code

**Hardware and reuse**
- Lecturer's scheme: GPIO5 straight to the servo signal, servo powered by the module, common GND, no transistor, no capacitors.
- Pot on GPIO4 (ADC1_CH3), 12 dB attenuation, 12-bit.
- Lecturer's register-level `pwm_hw.c` reused unchanged (13-bit LEDC, 50 Hz, no inversion, idle LOW).

**Structure**
- Files: `main.c`, `board_config.h`, `adc_hal.h/.c`, `pwm_hw.h/.c`, `servo_follow.h/.c`, `calib.h/.c`, all listed in `SRCS`.
- `servo_follow.c` is portable: no ESP headers, integers only, no float, no heap.
- **Only `main.c` includes `board_config.h`.** It copies the values into a `servo_follow_cfg_t` and passes it to `servo_follow_init()` (dependency injection).
- `static servo_follow_t s_follow;` in `main.c` — the struct itself (not a pointer), alive for the whole program. Config (`s->cfg.alpha_q8`, set once) and state (`s->ema_q8`, changes every call) live in the same struct; init **copies** the config.
- `const servo_follow_t *` in `deg_to_us`: it only reads.

**Math**
- Integer math, Q8 for α and for the EMA state; divide by 256 instead of shifting.
- `int32_t` for everything that gets subtracted; convert to `uint32_t` only at the end of `deg_to_us`.
- Multiply before dividing in both linear maps.
- Filter first (in ADC units), then window and clamp, then deadband on whole degrees.
- The first sample initializes the filter (no sweep from 0 at boot).
- `init` rejects `raw_at_0 == raw_at_180` (divide by zero) and `alpha_q8` outside 1…256.

**Interfaces**
- Reads return `bool` status and write data through a pointer (`hal_adc_read_raw(&raw)`, `servo_follow_update(..., &deg)`). Outputs are read only when the call returns `true`.
- The driver's `int` is read into a local `int`, then converted: `*raw_out = (int32_t)raw` (never cast the pointer).
- `%" PRId32 "` for printing `int32_t`.

**Loop and calibration**
- `vTaskDelay(20 ms)`, not `vTaskDelayUntil`: the LEDC hardware keeps the 50 Hz pulses on its own, so a slightly longer loop only makes the filter marginally slower.
- Log on every change (no rate limit). The deadband keeps a still knob silent, and the console always shows the true final angle. Too noisy → raise the deadband.
- `BOARD_CALIB_MODE` (0 normal, 1 pot, 2 servo); calibration runs after hardware init, before `servo_follow_init()`.

**`servo_follow.c` core (pseudocode)**

```
update(s, raw, *deg_out):
    first  = !started
    x_q8   = raw · 256
    ema_q8 = first ? x_q8 : ema_q8 + (x_q8 − ema_q8) · alpha_q8 / 256
    code   = ema_q8 / 256
    deg    = clamp((code − raw_at_0) · 180 / (raw_at_180 − raw_at_0), 0, 180)
    if first or |deg − last_deg| ≥ deadband_deg:
        started = true; last_deg = deg; *deg_out = deg; return true
    return false

deg_to_us(s, deg):
    deg  = clamp(deg, 0, 180)
    span = (int32) us_at_180 − (int32) us_at_0
    return (uint32) ((int32) us_at_0 + deg · span / 180)
```
